# Data dictionary

Generated by `uv run ncse assemble` from `src/ncse/dataset.py`; do not edit by hand. All tables are CSV files in UTF-8. An empty cell means no value.

Terms: a *passage* is a verbatim quotation from an article; a *statement* is one evaluation in it: one target (creator or work) × one criterion × one polarity (D-003). *Analyst* and *reviewer* are the two LLM steps: the analyst proposes statements, the reviewer may only delete them or lower their evidence level (D-005). Allowed values and their meaning are defined in `docs/annotation-guidelines.md` and `docs/evidence-and-review.md`.

## statements.csv

One row per evaluative statement.

| Column | Meaning |
|---|---|
| `statement_id` | Unique identifier of the statement: passage identifier + `-s` + number (D-003). |
| `passage_id` | Identifier of the passage (quotation) the statement rests on: article identifier + `-p` + number. Statements sharing a passage come from the same quotation. |
| `article_id` | Identifier of the article in the prepared corpus; the text is `texts/<article_id>.txt`. |
| `periodical` | The Leader or The Monthly Repository. |
| `issue_date` | Date of the issue (YYYY-MM-DD). |
| `year` | Year of the issue. |
| `part` | For a long article annotated in parts (D-034): the part the passage came from; else empty. |
| `quote` | The passage, exactly as it stands in the article's text file (OCR errors included). |
| `quote_start` | Position of the passage in the text file: characters from the start (counting from 0). |
| `quote_end` | Position just after the end of the passage. |
| `quote_match` | How the model's copy of the passage matched the text: exact (only spacing differs), normalised (same letters and digits) or approximate (a few characters differ; D-028). |
| `evaluative_expression` | The evaluative word or phrase, exactly as it stands in the text; it lies inside `quote`. |
| `expression_start` | Position of the evaluative expression in the text file. |
| `expression_end` | Position just after the end of the evaluative expression. |
| `expression_match` | How the model's copy of the expression matched (as `quote_match`). |
| `creator` | Value: the person whose work is judged (writer, composer, painter, dramatist, translator), as written in the source. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `creator_review`). |
| `creator_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `creator_evidence_analyst` | Evidence level given by the analyst, before review. |
| `creator_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `creator_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `creator_review_reason` | The reviewer's reason for that action. |
| `art` | Value: the art the work belongs to: literature, music, theatre, visual art or other. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `art_review`). |
| `art_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `art_evidence_analyst` | Evidence level given by the analyst, before review. |
| `art_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `art_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `art_review_reason` | The reviewer's reason for that action. |
| `work_title` | Value: the title of the judged work, as written in the source. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `work_title_review`). |
| `work_title_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `work_title_evidence_analyst` | Evidence level given by the analyst, before review. |
| `work_title_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `work_title_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `work_title_review_reason` | The reviewer's reason for that action. |
| `work_genre` | Value: the kind of work (novel, opera, sermon, history, ...), as written where possible. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `work_genre_review`). |
| `work_genre_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `work_genre_evidence_analyst` | Evidence level given by the analyst, before review. |
| `work_genre_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `work_genre_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `work_genre_review_reason` | The reviewer's reason for that action. |
| `polarity` | Value: positive or negative judgement. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `polarity_review`). |
| `polarity_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `polarity_evidence_analyst` | Evidence level given by the analyst, before review. |
| `polarity_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `polarity_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `polarity_review_reason` | The reviewer's reason for that action. |
| `sarcastic` | Value: yes if the evaluation is ironic (says the opposite of what it means), otherwise no. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `sarcastic_review`). |
| `sarcastic_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `sarcastic_evidence_analyst` | Evidence level given by the analyst, before review. |
| `sarcastic_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `sarcastic_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `sarcastic_review_reason` | The reviewer's reason for that action. |
| `criterion` | Value: the ground of the judgement: aesthetic value, moral value, usefulness, novelty or tradition. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `criterion_review`). |
| `criterion_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `criterion_evidence_analyst` | Evidence level given by the analyst, before review. |

| `criterion_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `criterion_review_reason` | The reviewer's reason for that action. |
| `quoted_source` | Value: whose opinion the critic reports; empty means the critic's own voice. Empty if the analyst left it empty. The value stays even if the reviewer deleted it (see `quoted_source_review`). |
| `quoted_source_evidence` | Evidence level after review: observed (the text says it), inferred (the text implies it), suggested (the model's expectation). Empty if the field is empty. |
| `quoted_source_evidence_analyst` | Evidence level given by the analyst, before review. |
| `quoted_source_assumption` | The analyst's assumption behind an inferred or suggested value. |
| `quoted_source_review` | What the reviewer did to this field: deleted, downgraded, or empty (nothing). |
| `quoted_source_review_reason` | The reviewer's reason for that action. |
| `evidence` | Evidence level of the statement after review: the lowest level among its fields that the reviewer did not delete (D-004). |
| `evidence_analyst` | Evidence level of the statement as the analyst gave it. |
| `deleted` | yes if the reviewer deleted the whole statement, otherwise no. Deleted statements stay in the table so that the review can be studied; filter on this column to use only kept ones. |
| `deleted_reason` | The reviewer's reason for deleting the statement. |
| `note` | The analyst's remark; required when `art` is other. |
| `flags` | Warnings from the code checks on this statement or its passage, separated by `; ` (for example observed_not_found, approximate_quote, repeated_statement; docs/output-format.md, section 3). They do not reject anything; they mark rows to look at. |
| `corpus_version` | Version of the prepared corpus the quotations refer to. |
| `analyst_model` | Model name of the analyst, as requested from the service. |
| `analyst_prompt_version` | Version of the analyst prompt (folder in prompts/analyst/). |
| `analyst_prompt_sha256` | First 12 characters of the checksum of the analyst instructions actually sent. |
| `analyst_run_id` | The analyst run that produced the accepted answer (see runs.csv). |
| `analyst_answered_at` | Date and time of the accepted analyst answer. |
| `reviewer_model` | Model name of the reviewer. |
| `reviewer_prompt_version` | Version of the reviewer prompt (folder in prompts/reviewer/). |
| `reviewer_prompt_sha256` | First 12 characters of the checksum of the reviewer instructions actually sent. |
| `reviewer_run_id` | The reviewer run that produced the accepted review (see runs.csv). |
| `reviewer_answered_at` | Date and time of the accepted review. |

## articles.csv

One row per article of the corpus.

| Column | Meaning |
|---|---|
| `article_id` | Identifier of the article in the prepared corpus. |
| `periodical` | The Leader or The Monthly Repository. |
| `issue_date` | Date of the issue (YYYY-MM-DD). |
| `year` | Year of the issue. |
| `heading` | Heading of the article, if any (from the corpus metadata). |
| `n_words` | Length of the article in words (from the corpus metadata). |
| `n_chars` | Length of the article in characters. |
| `n_parts` | Number of parts the article was annotated in (1 = sent whole; D-034). |
| `analyst_status` | accepted, failed, or not processed. |
| `reviewer_status` | accepted, failed, not processed, or outdated (the review belongs to an earlier analyst answer and is not used). |
| `in_dataset` | yes if the article's statements are in statements.csv: both steps accepted. An article with `in_dataset` yes and 0 statements was read and found to contain no evaluations. |
| `n_passages` | Number of accepted passages. |
| `n_statements` | Number of statements in statements.csv (deleted ones included). |
| `n_deleted` | Number of statements the reviewer deleted. |
| `n_failed_items` | Number of passages and statements set aside by the checks (failed_items.csv). |
| `errors` | Why a step failed, if it did. |

## failed_items.csv

Passages and statements of accepted analyst answers that the code set aside (D-027). They are not statements of the dataset.

| Column | Meaning |
|---|---|
| `article_id` | Identifier of the article. |
| `where` | Number of the passage or statement in the analyst's answer (p03, p03-s02). |
| `item` | passage (with all its statements) or statement. |
| `n_statements` | For a failed passage: how many statements were set aside with it. |
| `reasons` | Why the code set the item aside, separated by `; `. |
| `answer` | What the model wrote for this item (JSON), kept so that the failure can be checked. |

## runs.csv

One row per annotation run whose records were found.

| Column | Meaning |
|---|---|
| `run_id` | Identifier of the run (step + date and time it started). |
| `step` | analyst or reviewer. |
| `model` | Model name requested from the service. |
| `prompt_version` | Prompt version. |
| `prompt_sha256` | First 12 characters of the checksum of the instructions. |
| `settings` | Model settings sent with every request (JSON): temperature, length limit, and so on. |
| `started` | When the run started. |
| `finished` | When the run finished. |
| `requests` | Number of requests sent in the run. |
| `prompt_tokens` | Input tokens used. |
| `completion_tokens` | Output tokens used (reasoning included). |
| `used_in_dataset` | yes if at least one accepted answer in the dataset comes from this run. |
